# Console messages in the FireGL kernel driver

This is the catalogue of the messages the ATI FireGL kernel driver (`fglrx.o`, from the IP35 kernel set of IRIX 6.5.30) prints through the kernel's console printers. Each row is one call site: its address in the object, the routine it sits in, the printer, the format string, the values the format reads, and the condition that reaches the call. The table is [messages.tsv](messages.tsv). It is generated by [tools/message_sites.py](../tools/message_sites.py) from the object's `objdump -dr` output; the hand-written conditions are in [message-conditions.tsv](message-conditions.tsv).

Status: partial. Only the kernel driver object is catalogued. The X server module, the DRI and GLX libraries, the option ROM emulator and the diagnostics are not done (see [what is missing](#what-is-missing)).

## Table columns

- `label`, `routine`, `address`: the object, the routine containing the call, and the address of the call instruction, as `objdump` shows it in the object. The object's symbol table names only the exported routines. The static routines between them have no symbol, and `objdump` labels their code with the nearest earlier name. The compiler puts a routine's out-of-line blocks after its return, so code past a name's size stays with that name until a `daddiu sp,sp,-N` (a routine's entry) starts an unnamed one. From there the row says `sub_<address>`, the address of the first instruction of that routine, counting the few setup instructions the compiler hoists above the stack adjustment. 62 of the 225 rows are in unnamed routines.
- `kind`: `direct` for a call to a console printer; `wrapper` for a call to a routine of this object that calls a printer before it returns. A wrapper row lists the strings the call passes; the wrapper forwards its own argument, so the format is not named.
- `callee`: the printer (`cmn_err`, `printf`, `icmn_err`, `debug`, `assfail`), or the wrapper's name, or `sub_<address>` for unlabelled code inside a routine.
- `level`: for `cmn_err` the level it is passed in a0, for `assfail` the file and line.
- `format`: the format string the printer reads. `(format not recovered)` means the evaluator did not find the format register's value.
- `other_strings`: the values the format's conversions read, in order (`%s` strings and `%d`, `%x` constants). A `?` means the value was not known. Registers the format does not consume are not listed, because they hold stale values.
- `category`: `rom`, `interrupt`, `hang-recovery` and `attach` are keyword matches on the message and routine name, so they are a sort, not a reading. `assert`, `trace` and `other` are the rest. `trace` rows are `debug` calls, which pass a flag name in a0.
- `guard`: how the call's basic block is reached, read from the instructions: the conditional branch that jumps to it, or the branch that falls through into it. A `join` block with several branches lists how many there are.
- `condition`: the written condition, where someone read the code. `not yet read` otherwise.
- `grade`: `inferred` (the guarding branch and the value it tests were read), `partial` (the branch was read, the value was not traced), or `unread`.

## How the values are found

`objdump -dr` gives each relocation for the 64-bit address sequences the kernel uses (`lui` and `daddiu` with `HIGHEST`, `HIGHER`, `HI16` and `LO16`). The evaluator adds them up per register:

- Callee-saved registers (s0 to s8, gp, sp) keep their values across calls. The format and the callee of a call often come from one of them, so the value comes from every path into the call. Where the paths agree, the value is used; where they disagree, the callee is left unknown.
- Caller-saved registers come from the basic block that holds the call, with its delay slot included.
- Position-independent code adds a run-time base to symbol addresses. The base is not known to the evaluator, so the symbol and offset are kept and the value is marked approximate. The offset within the section is what the relocations give, so the string is still found; the run-time base only moves the section.

A string is read from the object's .rodata or .data at the resolved offset, up to its NUL.

## Coverage

Of the 225 rows in `fglrx.o`: 92 direct calls with no category keyword, 20 attach, 3 expansion ROM, 2 interrupt, 8 assertions, 7 `debug` trace calls; wrappers make up the rest (79 with no keyword, 13 hang-recovery, 1 interrupt). Seven rows carry a written condition: five `inferred` and two `partial`. The rest say `not yet read`.

The attach and ROM rows in `fglrx_attach` are the ones read first. The seven written conditions are the PIO and BAR mapping failures (config space, mmio, mem(0), reg(2), the expansion ROM window, vga framebuffer, legacy PIO) and the ROM signature messages. The two ROM rows marked `partial` name the branch and the register they test, not the source of that register.

## Known limits

- A value that sits in a callee-saved register is shown only when it is a symbol (the base of a string table) or when the call's own block writes it. A constant carried in from earlier code is `?`, because it may be a loop index or a value set on another branch arm.
- A callee in a callee-saved register is resolved path by path. Some sites have paths whose values differ; those callees stay unknown, so the messages behind them are missing from the table. The clearest case in this object is `fglrx_attach`, where s7 holds `cmn_err` on one path and `GfxBoardInitSema` on another.
- A wrapper row is included only when its body prints before returning. Its format argument is not followed, so the row says which strings were passed, not which one is the message.
- The `debug` calls pass a tag and a second string whose meaning the object does not state. They are listed as trace calls and not read further.
- Some `cmn_err` sites have a format that the evaluator did not recover (five rows). They need a read of the routine.
- The file names passed to `assfail` are the object's build paths. They are kept because they are strings the object prints.

## What is missing

- The X server module `fglrx_drv.so`: calls go through the GOT and print through the X server's message functions. The GOT-slot names need the dynamic symbol table, which this table generator does not read yet.
- `fglrx_dri.so`, `fglrx_glx.so` and `libfglrxdrm.so`: the DRI and GLX messages and the DRM library's messages.
- The option ROM emulator (`vga.a` members and `biosemu`): the BIOS messages and the ROM-run failures.
- The diagnostics `olsg`, `olsgsys`, `vpm`, `sg2flash`, `gfxtopology` and `sgcombine`.
- Written conditions for the interrupt and hang-recovery rows. Those include the interrupt connection failure at `fglrx_attach` 0x1e50, the error handler at 0x4590 and the hang message in `_r6x_resetPM4` (through the wrapper at 0x136e4).

To regenerate the table, from the repository root inside the toolchain environment:

    retools/tools/re-run python3 tools/message_sites.py root/usr/cpu/sysgen/IP35boot/fglrx.o fglrx.o \
        --conditions evidence/message-conditions.tsv --tsv evidence/messages.tsv
