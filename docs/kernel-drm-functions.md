# The FireGL kernel driver: lock, map, buffer and context routines

`usr/cpu/sysgen/IP35boot/fglrx.o` is the 64-bit kernel object ATI ships for the FireGL cards (see [Kernel attach path](kernel-attach.md)). It is relocatable and has a symbol table, so a call to another object is a relocation and the addresses below are offsets in the object. The device record is the per-board structure that the attach path builds (its doubleword at +0 is the lock handle passed to the spin-lock and semaphore routines, +104 the pointer to the shared lock word, +848 the head of the map list whose sentinel is the address record +864). Routines at 0xed68, 0xed94, 0x13eac, 0x16168, 0x1613c, 0x1b98c, 0x1f784 and 0x1f7b0 only spill their argument registers and return: they are the compiled-out debug prints, and the entries call them logging stubs. Routines at 0xba2c, 0xbac0, 0x1b8f8 and 0x160a4 print through `cmn_err` and `icmn_err` and the entries call them error prints. The labels follow `AGENTS.md` section 5.

## Hardware lock, takedown and mapping

- `firegl_lock_device` (`fglrx.o`, 2656 bytes at address 0x16194): takes the shared hardware lock for a rendering context, sleeping until it is free, then switches the chip to that context.
  The arguments are the device record (a0, kept in s0), the file (a1), the context number (a2, kept in s6) and the request flags (a3, kept in s1).
  A zero lock pointer at record +104 prints "trying to lock without a valid SAREA setup!" through the error print, loads the doubleword at the fixed kernel address -16360, and when that and its +776 pointer are nonzero calls `sigtopid` with the word at +16 of that pointer and 15; otherwise it takes the id from `kthread_get_pid` first. It returns -19 on this path.
  Otherwise it logs the request, then loops. A zero lock pointer inside the loop logs "device has been unregistered" and returns -19. When bit 29 of the context number is clear, it takes the spin lock (class 4), reads the context table pointer at record +952 and the entry at the context number times 8, raises that context's use counter at entry +16392 with `__ke_atomic_inc`, drops the lock and logs the count; an empty entry logs "context %d no longer valid!" and returns -22.
  It then takes the queue mutex for the queue at record +128 (`__ke_get_queue_mutex`, `mutex_lock` with priority 25) and the spin lock (class 5). When the file's word at +48 is not 1 and the context number is nonzero it drops both, logs "thread killed by signal" and returns -4.
  The lock word is updated with a load-linked and store-conditional loop: when its bit 31 is clear it stores the context number with bit 31 set, otherwise the old word with bit 30 set. When the low 30 bits of the stored word equal the context number the lock is granted: the routine stores the caller's process id (`__ke_getpid`) at +112, zero at +120 and the tick count (`__ke_jiffies`) at +136, raises the counter at +92, logs "got lock", releases the spin lock and the mutex and falls into the switch step.
  When the lock is held by another context it releases the spin lock, lowers the use counter again, raises the counter at record +100 and sleeps on the queue (`__ke_sleep_on_queue` with record +128). A result of -2 is checked with `vproc_lookup` on the word at +116: when the holder no longer exists it logs "stale dev: %s lock held by pid: %d cleared by sentinel", calls `firegl_lock_free` with the lock word's low 30 bits and tries again. Any other negative result goes to the switch step without the lock.
  The switch step calls `assign_cursighold` with record +1032 and a mask word of 0x6c00000, zeroes the word at +20 of the doubleword at +1208 when the word at +1184 is set, takes the semaphore at record +0, empties the dead-queue list at +1144 and releases the semaphore, then calls `_r6x_switch_context` with the context number (or 0 and the message "switch context to DRM_KERNEL_CONTEXT" when no table entry was found). When flag bit 1 was requested and the lock word shows the caller's process id as owner it calls `_r6x_WaitNotBusy`.
  The dead-queue drain calls `firegl_free_buffer_queue` for each queued element; one that still has mappings is logged ("outstanding mapping for buffer queue 0x%08lx - put back to dead buffer queue!") and put back, one that is freed raises the counter at +1160.
  A final log reads "context %d has lock" or "context %d got interrupted". The routine returns 0, -4, -19 or -22. **Inferred.**
- `firegl_takedown` (`fglrx.o`, 2376 bytes at address 0x105c4): undoes the device set-up when the last open closes, releasing every resource the first open created.
  It takes the device record in a0 and returns what the last logging stub returns. It calls `firegl_remove_all_drawables` and `firegl_unregister_all_textures`, then `_r6x_EnableStereo(record, 0)` and zeroes the doubleword at +11664 when that doubleword is nonzero.
  Under the semaphore at record +0 it empties the dead buffer-queue list at +1144 by calling `firegl_free_buffer_queue` on each element (a nonzero result is logged as "outstanding mapping ... memory leak probable!" and the element is put back, a zero result raises the counter at +1160), logs "dead buffer queue not empty!!" if anything is left and zeroes the list head.
  Under the semaphore it frees the unique name strings at +56 and +40 with `drm_free` (length from `__ke_strlen` plus 1, type 2), clears the 16-slot hash tables of 16-byte entries at +536 (type 3, 24-byte nodes) and +144 (type 18) and the list at +936 (type 5).
  It walks the map list from +848 to the sentinel +864 and handles each map by its type word at +16 through a 14-entry jump table: register maps and frame-buffer maps with a write-combining region (word at +32 not negative) delete it with `__ke_mtrr_del` and are unmapped with `drm_ioremapfree`, shared-memory maps are released with `drm_vfree`, the other types only log; nodes are then released with `drm_free` (length 72, type 4) and the list is reset (+920 zero, +928 the address record +792, +848 the sentinel).
  It then frees every context slot downward from the count at +944 (each page block with `drm_free_pages_consistent`, type 9, and the table at +952 with `drm_free`, length 8 times the count at +948), wakes and frees the wait queues at +11640 and +128 when present, zeroes the lock pointer at +104 and the owner words +112 and +120, and terminates the memory apertures at +11536 and +11544 with `firegl_term_aperture` (after `firegl_aperture_size`). It ends by calling `_r6x_close_irq` when the handle at +11624 is nonzero and logs "takedown finished". **Inferred.**
- `firegl_mmap` (`fglrx.o`, 1748 bytes at address 0xc16c): the memory-map handler for a user mapping of the device; it finds the registered map that the requested offset names and maps it into the process.
  The arguments are a0 (passed to `__ke_get_file_priv`, kept in s5) and the mapping descriptor (a1, kept in s2); the device record is the doubleword at +72 of the file's private record. It reads the mapping's start, end and offset with `__ke_vm_start`, `__ke_vm_end` and `__ke_vm_offset`.
  Under the semaphore at record +0 it walks the map list from +848 for the entry whose first doubleword equals the offset; none logs "No map found!" and returns -22. A map whose flag word at +20 has bit 0 set needs `__ke_capable(0)` to be nonzero, otherwise "Mapping not permitted!" and -1. A map smaller than end minus start logs "invalid size" and returns -22.
  The map type (word at +16, below 14) selects a mapping call: types 0 and 1 call `__ke_vm_map` with mode 0 and the flag (map +20 bit 1) as the fourth argument, type 2 with mode 1, type 10 with mode 2 (after checking that the doubleword at +24 equals the map address plus 16400, else "Inconsistent kernel data!" and -22), type 11 with mode 3 and type 13 with mode 0 and a zero flag. Types 3 to 9 and any value of 14 or more log "Invalid map type!" and return -22. A negative `__ke_vm_map` result is returned after the semaphore is released.
  On success it releases the semaphore, calls `v_mapphys` with the doubleword at +40 of a0, the map's doubleword at +24 and the size, and returns its result when nonzero. Otherwise, with bit 1 of the mapping's word at +40 clear it calls `as_lookup_current` and a method through the address space (+16, then +144) with a four-word request; it then logs the physical and virtual address from `v_getaddr`, calls `drm_vm_open` and returns 0. **Inferred.**
- `firegl_addmap` (`fglrx.o`, 1684 bytes at address 0x1bc50): registers one memory map for the device, allocating the backing store where the map type needs it.
  The arguments are the device record (a0, kept in s3) and a map request (a1, kept in s1). An offset that is not a multiple of 16384 prints "map offset 0x%lx - not page aligned" and a size that is not prints "map size %ld - not page aligned"; both return -22.
  Under the semaphore at record +0 (`__ke_down_struct_sem`, second argument 0): a request whose flags word at +20 has bit 5 set (the shared-area map) and a SAREA already present at +104 logs "Only one SAREA allowed! Setting offset ..." and replaces the request's offset (the doubleword at +0) by that SAREA's. In every case it then calls `calc_offset` with the device record and the type word at +16 and stores the result as the offset. The existing map list from +848 is searched for that offset; a match with equal size, type and flags logs "Existing map", copies the old map's address (+24) into the request, releases the semaphore and returns 0; a match with different values logs "cannot create different map at same offset" and returns -22. With no match the type word is initialised: +32 gets -1 and the new node's +56 and +64 point at itself.
  A new map is built by type (a 14-entry jump table on the word at +16). Type 1 (the register map) logs and returns -22 when the record already holds one (the doubleword at +1000 is nonzero, "Only one IO map allowed!"). Types 0 and 1 ask `__ke_config_mtrr` and, when it is nonzero and the type is 0 or flag bit 4 is set, reserve a write-combining region with `__ke_mtrr_add_wc` (offset, size) and store its index at +32; a failed reservation is logged and ignored. Type 0 takes its address (+24) from the doubleword at +632 of the structure that record +11656 points to; every other type except 2 calls `drm_ioremap` with the offset and size and stores the result at +24. For type 1 the address is also stored at record +1000 and bits 31 to 16 of the word at offset 0xf18 of the mapped registers at record +1008.
  Types 10 to 13 only log their names. Type 2 (shared memory) calls `drm_vmalloc` for the size; a null result logs "vmalloc failed!" and the result is -12. When the flag word at +20 has bit 5 set it also stores the address as the SAREA at record +104, the address plus 64 at +400 and the address plus 2200 at +992 (a second SAREA logs "Only one SAREA allowed!" and gives -22). Any other type logs "type = UNKNOWN" and gives -22.
  The new map is linked at the tail of the list (its +56 and +64 take the old tail's links from record +928, the old tail's +56 and record +928 take the new map), "added new map" is logged and the semaphore released. The result is 0, -12 or -22. **Inferred.**
- `firegl_alloc_bufs` (`fglrx.o`, 1540 bytes at address 0x198f4): the allocate-buffer-queue request; it copies a 24-byte request in from user space, creates a buffer queue of the requested kind and returns the queue's mapping handle to the caller.
  The arguments are the file (a1, passed to `__ke_get_file_priv`) and the user request pointer (a3, kept in s4); the device record is the doubleword at +72 of the private record. `__ke_copy_from_user` of 24 bytes failing returns -14; a zero size at request +12 returns -22.
  The request's kind (word at +8, below 7, through a 7-entry jump table) selects the pool: kinds 0 and 1 use pool 0 without a mapping (s5 = 0), kind 2 pool 2, kinds 3, 4, 5 and 6 pools 3, 4, 5 and 6; kinds 4, 5 and 6 are the ones that go through `alloc_cache_ram` (s5 = 1). Other kinds log "Invalid buffer type!" and return -22. The caller's privilege is tested with `__ke_capable(0)` and the request word at +20 is replaced by -1 when it fails.
  It then calls `alloc_cache_ram` (kinds 4 to 6) or `create_buffer_queue` with the file's private record, the size at +12, the pool, a result slot and the word at +20; a failure is logged and returned, except that pool 3 retries in pool 2 ("retry using LFB pool..."). On success it logs "new buffer queue", stores the queue's doubleword +16 into +32 and the kind into +44, and picks the mapping type by the queue's kind word (11, 12 or 13 for the mapped kinds, with the "RETRY" fallback when the queue ended in pool 2) before mapping the queue through `firegl_addmap`; a failure frees the queue with `firegl_free_buffer_queue` and returns -22. When `__ke_debuglevel` is negative and the queue has a mapping, the doublewords of the mapping (the pointer at queue +48, one per 8 bytes of the length at +32) are filled with the value 0xdeadbeaf by an unrolled loop; the queue is added with `add_buffer_queue`, the 24-byte reply is copied out with `__ke_copy_to_user` (failure frees the queue and returns -14) and the routine returns 0. **Inferred.**
- `firegl_lock_memory` (`fglrx.o`, 1456 bytes at address 0x1fbd4): locks a range of user pages in memory and writes the physical address of each page back to the caller.
  The arguments are the file (a1) and a user request pointer (a3, kept in s4); the device is the doubleword at +72 of the file's private record. It copies 32 bytes of request in with `__ke_copy_from_user` (failure returns -14); a zero address (+8) or length (+16) returns -22.
  The page count is the sum of the in-page offset (address & 0x3fff) and the length, rounded up to 16384-byte pages. `drm_mem_inc_locked_pages` is asked to account for them (a negative result is returned as is) and the user list pointer (+24) is checked with `__ke_verify_write_access` (failure releases the pages and returns -14). A 32-byte record is taken with `drm_alloc` (type 17; failure returns -12) holding the address, length and list pointer; the caller's effective capabilities are saved (`__ke_get_cap_effective`), raised when `__ke_capable(1)` fails, and the pages are locked with `__ke_sys_mlock` (an error is logged as "firegl_sys_mlock: error = %i", the capabilities restored, the record and the page accounting released, and the error returned).
  For each page it translates the virtual address with `__ke_get_vm_phys_addr` (current mm from `__ke_current_mm`), logs "page %d: virt. adr ... -> phys. adr ..." and copies the 8-byte physical address into the user list with `__ke_copy_to_user`; a failed copy undoes the lock with `__ke_sys_munlock` and returns -14. The capabilities are restored, the record is filed with `add_memlock`, the request is copied back out (32 bytes) and the routine returns 0, logging "%d pages locked.". **Inferred.**
- `firegl_umm_init` (`fglrx.o`, 1316 bytes at address 0x20534): sets up the unified memory apertures the driver hands out of the board's frame buffer.
  The arguments are the file (a1) and the user pointer to a 24-byte request (a3). A failed `__ke_copy_from_user` returns -14. The request holds the start (bytes 8 to 11), the size (bytes 12 to 15) and the invisible-part size (bytes 16 to 19). A start that is not 16384-aligned logs "invalid UMM alignment!" and returns -22.
  Under the semaphore at record +0 it searches the map list from +848 for the frame-buffer map whose first doubleword equals the request's doubleword at +0, returning -19 when none is found. The start, start plus size and the map's end must all lie inside the map (else "Invalid UMM setup!" and -22); a record whose flag word at +11528 is already 1 logs "UMM area already initialized!" and returns -22.
  It stores the start at +11552, creates the visible aperture with `firegl_init_aperture` (size shifted right by 14) into +11536 (failure logs and returns -12), logs the element count (`firegl_aperture_size`), stores the invisible-part offset at +11560 and, when an invisible size is requested, creates a second aperture at +11544 (on failure it terminates the first and returns -12). It then calls `_r6x_InitMaskRamSize`, and for each nonzero size it reports at +11568, +11584 and +11600 creates a further aperture stored at +11576, +11592 and +11608 (the mask, Z mask and HiZ apertures; a failure only logs). It sets the flag at +11528 to 1 and returns 0. **Inferred.**
- `fglrx_hpipe_discover` (`fglrx.o`, 1416 bytes at address 0x5de0): builds the hyperpipe state table once, matching each board's attached compositor to its slot and port.
  A flag word at +12 of the state anchor is test-and-set with a load-linked loop; when it was already set the routine returns 0. Otherwise it initialises the spin lock "FglrxHpipeStateLock" and takes it with `mutex_spinlock`. The state block (9744 bytes) is cleared with `bzero` or, when none exists, allocated with `kmem_zalloc`; an allocation failure prints "%s: Error allocating %d bytes for Hyperpipe State" and returns 12. The word at +9740 is set to -1 and 128 spin locks of 40-byte entries are initialised.
  For every board in the board table it reads the record's word at +328: bits 15 to 8 give the compositor index, bits 1 to 0 the port. An index of 0 or above 64 prints "pipe %d invalid compositor attached value 0x%x (max %d)"; a slot whose pointer and port pointer are already filled prints "another compositor showing duplicate index %d or serial_id 0x%llx on port %d! (skipping entry)". Otherwise it stores index minus 1 at slot +5080, the index at +5088 and the board record at +5096 plus 8 times the port, links the slot into the board record at +752 and keeps the highest index at +9740.
  It then records the attached count at +8200 and lists up to 128 connections of three words each (board number from record +428, port, compositor index) from +8204, printing "number hyperpipe connections (%d) exceeded max (%d)" past 128, appends every board whose compositor link at +752 is empty with -1 in the last two words, sets the state flag word at +0 to 1, releases the lock with `mutex_spinunlock` and returns 0. **Inferred.**

## Contexts and the device ioctl entry

- `_firegl_alloc_ctx` (`fglrx.o`, 1400 bytes at address 0x1d968): allocates one rendering context block and a handle for it.
  The arguments are the device record (a0, kept in s1) and a pointer to an error word (a1, kept in s5). It computes the page order for 16488 bytes with `drm_order` and allocates them with `drm_alloc_pages_consistent` (type 9); a failure stores -12 in the error word and returns 0.
  Under the spin lock (class 4) it scans the context table at record +952 downward from the count (`__ke_atomic_read` of the counter at +944) for the first empty slot ("found free ctx slot %d"); with no free slot it logs "no free ctx found" and, when the count has reached the table size at +948, doubles the table (`drm_alloc` of 8 bytes per slot, 2 slots for an empty table, old entries moved with `__ke_memcpy` and the old table released with `drm_free`; failure stores -12). A handle with any of its top three bits set logs "handle %d overlaps with mutex ids!" and fails with -12.
  It clears the block with `__ke_memset`, stores the handle at block +16388 and the page order at +16384 and runs `_r6x_init_hw_ctx` on it; a nonzero result is logged ("Failed to initialize hw context %d (%d)"), the pages freed and that result stored in the error word. Otherwise the block goes into the table, the counter is raised (`__ke_atomic_inc`) when the slot is above the old count, the lock is released and the block is returned, with "=> new RE context" logged. **Inferred.**
- `fglrx_ioctl` (`fglrx.o`, 1296 bytes at address 0x3b74): the character-device ioctl entry; it checks the open device and dispatches a request.
  The arguments are the device number word (a0), the command (a1, kept in s0), the user pointer (a2, kept in s1) and the result pointer (a5, kept in s3). Bits 26 to 18 of the number select the board; a zero board field calls `hwgraph_fastinfo_get` and returns 19. The low 18 bits (the slot) must be at least the word at `.data`+320 and below 65536, otherwise a message goes to `cmn_err` and 19 is returned; an empty per-open table entry does the same. The entry's first doubleword is the board record (s2). A word of a per-processor table is incremented first.
  Commands with the high half 0x6667 and a low half below 30 call the handler stored at `.data`+344 plus 8 times the low half with the board record, the user pointer and the result pointer. The command 7777 calls `fglrx_test_ioctl`; 102 copies 184 bytes from record +224 out; 101 sums the board counts of the table at `.data`+312 and copies the 4-byte total out; 105 reads a board number, and when it is below `GfxBoardLimit` copies that board's table word out, else returns 19. A command whose bits 15 to 8 are 100 calls `firegl_ioctl` with a0 = 0, the per-open entry, the command and the user pointer.
  Bit 30 of the command requests a configuration-space read of (bits 23 to 16) bytes at offset (bits 15 to 0): `pciio_config_get` on the connection at record +408, left-aligned in a doubleword and copied out with `copyout`. Bit 31 requests a write: `copyin` of that many bytes, shifted right to align them and passed to `pciio_config_set`.
  Copy failures give 14. The routine stores 0 through the result pointer when the error is 0 and -1 otherwise, and returns the error. **Inferred.**

## Map removal, context creation and buffer queues

- `drm_addmap` (`fglrx.o`, 1280 bytes at address 0x1c6b8): the add-map request from user space; it copies a 40-byte request in, creates the map and copies the reply back.
  The arguments are the file (a1) and the user pointer (a3, kept in s2); the device record is the doubleword at +72 of the file's private record. A zero from `__ke_file_rw_open` on the file logs "EACCES!" and returns -13; a failed `__ke_copy_from_user` of 40 bytes returns -14.
  The type in bytes 16 to 19 of the request picks the path. Types 0, 1 and 2 get a 72-byte node from `drm_alloc` (type 4; failure logs "ENOMEM!" and returns -12), cleared with `__ke_memset` and filled with the request's five doublewords, and `firegl_addmap` is called with it. A zero result logs "new map!" and keeps the node; a result of -16 logs "existing map!", makes the status 0 and frees the node; another result is the status and the node is freed. The node's first doubleword becomes the reply's doubleword at +24.
  Type 10 (the context map) takes the context number from the request's word at +4, rejects one that is 0 or below or not below the context count (`__ke_atomic_read` of the counter at +944), under the spin lock (class 4), with "invalid context %d" and -22, and otherwise logs "pctx=0x%08lx id=%d" (the table entry at +952 and its word at +16388) and returns that context pointer in the reply. Any other type logs "invalid map type %d" and returns -22.
  The reply is copied out with `__ke_copy_to_user` (40 bytes; failure logs "cannot access user request buffer" and the status is -14), the node is freed with `drm_free` (72 bytes, type 4) when one was kept for freeing, "handle=0x%08lx" is logged and the status is returned. **Inferred.**
- `firegl_rmmap` (`fglrx.o`, 980 bytes at address 0x1c2e4): removes the registered map whose offset the caller names, releasing what its type holds.
  The arguments are the device record (a0, kept in s4) and the offset (a1, kept in s3). Under the semaphore at record +0 it walks the map list from +848 to the sentinel +864 for a node whose first doubleword equals the offset; none logs "map not found!" and returns 0 after releasing the semaphore.
  The type word at +16 selects the action through a 14-entry jump table: types 0 and 1 delete the write-combining region when the word at +32 is not negative (`__ke_config_mtrr` first, then `__ke_mtrr_del` with that word, the offset and the size) and unmap the node's address at +24 with `drm_ioremapfree`, and type 1 also zeroes the record's doubleword at +1000; type 2 releases the memory with `drm_vfree` and, when the flag word at +20 has bit 5 set, zeroes the lock pointer at +104 and the owner words +112 and +120, wakes the queue at +128 with `__ke_wake_up_interruptible` and zeroes the doubleword at +400; type 3 unmaps the address at +24 when it is nonzero and zeroes it; types 10 to 13 only log the type; other types log "type UNKNOWN".
  It then unlinks the node (the neighbours' +56 and +64 links are joined, the node's own links point at itself), releases the semaphore and logs "map 0x%08lx removed". The node itself is not freed here. **Inferred.**
- `fglrx_map` (`fglrx.o`, 976 bytes at address 0x4084): the device-map entry for a user mapping of a board region or of a driver map.
  The arguments are the device number word (a0), the second word (a1), the offset (a2), the length (a3) and the protection flags (a4); the second word is stored in the per-open record's doubleword at +40. Bits 26 to 18 of a0 pick the board (zero calls `hwgraph_fastinfo_get` and returns 19); the low 18 bits index the per-open table and must lie between the word at `.data`+320 and 65536 (a message goes to `cmn_err` and 19 is returned otherwise, also for an empty slot).
  Protection bit 2 set returns 13. For the offsets 0x80100000 to 0x80700000 in steps of 0x100000 it takes a base and a length from the board record: the doublewords at +528 and +536, +632 and +640, +608 and +616, +656 and +664, +552 and +568, +584 and +592, +680 and +688 respectively. The requested length rounded up to 16384 must not exceed the region length (plus the base's in-page offset) rounded up, else it returns 5. It then calls `v_mapphys` with the page-aligned base and the rounded length; a nonzero result is returned. With bit 1 of the flags clear the routine also calls `as_lookup_current` and `v_getaddr` and runs a method of the address space with a request that holds the type 4, the flag byte and the address.
  An offset outside those seven values is passed to `firegl_mmap` with a built descriptor holding the length, the offset shifted right by 14 and the flags. **Inferred.**
- `firegl_lock` (`fglrx.o`, 1188 bytes at address 0x16bf4): the lock ioctl; it validates the requested context and takes the hardware lock for it through `firegl_lock_device`.
  The arguments are the file (a1) and the user pointer (a3); the device is the doubleword at +72 of the file's private record. It copies 8 bytes in (a failure returns -14). A zero context number returns -22 after logging "Process %d is using kernel context 0x%08x"; a number with bit 31 or bit 30 set logs "Process %d is using illegal context/mutex 0x%08x" and returns -22.
  When bit 29 is clear the number is a context index: it must be below the counter at +944 and have a nonzero entry in the table at +952 (read under the spin lock, class 4); otherwise it logs "Process %d is using illegal context 0x%08x", signals the process (`sigtopid` with 15, the same lookup as `firegl_lock_device` uses) and returns -22. When bit 29 is set `firegl_valid_mutex` must accept it, else "illegal mutex" and -22.
  It then calls `firegl_lock_device(record, file, context, word at +4 of the request)`. On success it first logs "got lock -> set lock.priv", stores the private record at record +120 and the context number at +48 of the private record. Either way it then calls `force_resched` and returns the result of `firegl_lock_device`, which is 0 on success. **Inferred.**
- `create_buffer_queue` (`fglrx.o`, 1120 bytes at address 0x18e60): builds one buffer queue descriptor and backs it with pages or with a slice of the unified memory aperture.
  The arguments are the file's private record (a0), the size in bytes (a1), the pool type (a2), a pointer for the result (a3) and a requested aperture offset (a4, -1 for any). A 112-byte descriptor comes from `drm_alloc` (type 6; failure returns -12) and is cleared with `__ke_memset`. Its word +0 holds the type and its doubleword +16 the size rounded up to 16384.
  Pool types 0 and 1 take pages from `drm_alloc_pages_consistent` (the order from `drm_order`): the descriptor's +8 gets the block and +72 its physical address, and a failure frees the descriptor and returns -12. Pool types 2 and 3 use the aperture at record +11536 (visible) or +11544 (invisible) and the offset words at +11552 or +11560; with the unified memory not initialised (word at +11528 zero) they log "UMM not initialized!", free the descriptor and return -19.
